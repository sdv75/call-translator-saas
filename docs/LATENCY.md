# Текст разговора и замеры задержки

В версии 0.1.4 вкладка «Разговор» показывает два направления: ваши слова и перевод собеседнику; его слова и перевод вам. Предварительное распознавание показано курсивом с многоточием, оно может измениться. Только окончательные сегменты переводятся и сохраняются в полной локальной стенограмме. «Открыть отдельно» оставляет текст в отдельном окне рядом с Meet. Настройка аккаунта, языков, голосов и звука находится на отдельной вкладке.

«Скорость перевода» показывает последние числовые замеры обоих направлений. Выгрузка содержит только направление, последовательность и времена: без текста, идентификаторов аккаунта, ключей и аудио. Полные тексты остаются в локальной IndexedDB; ограниченный живой экран последних фраз хранится в доверенном chrome.storage.session, не отправляется на сервер хранения стенограмм.

| Поле | Что измерено |
| --- | --- |
| translation_queue_ms | Ожидание подтверждённой фразы до начала серверного перевода |
| translation_ms | Серверный запрос перевода, включая соединение с провайдером |
| voice_queue_ms | Очередь клиентской озвучки в своём направлении |
| tts_ms | Запрос к native host, его очередь, локальный синтез и передача WAV |
| decode_ms | Декодирование WAV браузером |
| routing_ms | Подготовка защиты от эха и передача звука в страницу Meet |
| playback_queue_ms | Расчётное ожидание старта в очереди локального AudioContext |
| after_recognition_ms | От получения окончательного текста браузером до расчётного начала локального воспроизведения; не включает доставку звука по WebRTC собеседнику |
| stt_backlog_ms | Уже отправленное STT аудио минус конец диапазона результата; включает особенности сегментации, не является точным RTT распознавания |

Этапы перекрываются, их нельзя безусловно складывать в точную задержку от конца человеческой речи до удалённого динамика. STT start/duration описывают диапазон аудио, а is_final отличается от предварительной гипотезы: [первичная документация Deepgram](https://developers.deepgram.com/docs/understand-endpointing-interim-results).

При включённой защите от эха микрофон временно передаёт нулевые кадры во время слышимой локальной озвучки и её хвоста. Это не полноценное эхоподавление: речь, произнесённая в этот период, не попадёт в распознавание. В этот момент показывается жёлтое предупреждение, в диагностике накапливается suppressed_ms. В наушниках защиту можно выключить для одновременного разговора.

## Проверка 2026-11-11

- Локальный прогретый синтез фиксированных фраз: русский 723 ms при 3285 ms аудио, украинский 478 ms при 2844 ms аудио. Подготовка моделей до звонка: 17392/14109 ms. Это единичный замер текущей Windows, не гарантия для других ПК.
- Настоящие провайдеры на VPS: три раунда синтетических ru/uk фраз, пачки по 25 кадров, 15900 ms на направление. Получены 4 перевода в каждом направлении (сегментация провайдера), штатный user_stop. Начало тестовой фразы распознано и сохранено в переводе обоих направлений.
- translation_ms median 279, max 639; translation_queue_ms median 4, max 14; stt_backlog_ms median 450, max 2200. Отчёт `build/vps-latency-probe.json`, без текстов. Реальные пользовательские база/баланс/аудио не использованы.
- Устранена блокировка чтения STT на время предыдущего перевода; промежуточные и окончательные результаты читаются независимо. Переводы сохраняют порядок внутри направления. Запись IndexedDB не блокирует запуск TTS; при ошибке журнала сохраняется прежнее безопасное завершение звонка.

Точная причина пропуска фразы в разговоре пользователя не доказана. Живой Meet с новым UI, физическое воспроизведение и качество голоса на слух этим тестом не проверены.
