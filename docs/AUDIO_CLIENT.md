# Экспериментальный аудиоклиент

Расширение загружается через Load unpacked из `extension`; требуется отдельный установленный локальный компонент и два выбранных голоса. Готового установщика пока нет. Для технических проверок подготовлены uk/en. API принимает ru, но без проверенного русского голоса запуск такой пары отклоняется.

До запуска звонка расширение проверяет активную вкладку Meet, доступные audio senders, серверный флаг аудио, привязку устройства, баланс и голоса. Native begin-call прогревает оба голоса до WebSocket. После разрешения захвата выбранной вкладки запускаются offscreen AudioWorklet и подмена исходящей audio track. Передача кадров разрешается только после готовности сервера и микрофона. Доступ к вкладке запрашивается действием пользователя; ранее открытый Meet нужно перезагрузить после установки расширения.

`meet.js` следит за audio senders с document_start; `translate.js` заменяет только аудиодорожки. Микрофон идёт в outgoing, звук вкладки — в incoming. Входящий перевод воспроизводится в offscreen вне захватываемой вкладки, исходящий отправляется собеседникам через replaceTrack. «Слышать свой перевод» меняет только локальный монитор исходящего звука (0 или 0,55). Рекомендуются наушники; реальная проверка акустического эха ещё нужна. Видео не меняется.

Каждое направление обрабатывается последовательно, с проверкой sequence и ограничением очереди. Переполнение сети, очереди или слишком длинное отставание останавливает перевод. Stop немедленно прекращает захват и запланированное воспроизведение, восстанавливает микрофон и ограниченно ожидает финальную стенограмму. Mute и новая дорожка, поставленная самим Meet, сохраняются. Потеря native host, вкладки, worker или сервера приводит к остановке; повторный запуск выполняется вручную. При ошибке восстановления интерфейс сообщает её, а не показывает успешное восстановление.

Учётные данные устройства доступны только контекстам расширения. MAIN world получает sessionId, URL worklet и звук; OAuth/provider keys там отсутствуют. Сообщения страницы не могут управлять native host, читать аккаунт или экспортировать стенограммы. Сохранённый sessionId защищает новый звонок от запоздавших кадров прежнего.

Стенограммы хранятся только в IndexedDB нового расширения: база `ct-saas-transcripts`, сессии и события. Recognized сохраняется до перевода; translation дополняет ту же запись по session/direction/sequence. Экспорт создаёт локальный HTML `YYYY-MM-DD_HH-MM-SS.html`, с экранированным текстом. Старые базы персонального расширения не читаются. Ошибка хранилища не мешает освобождению аудиоресурсов и отображается пользователю.

## Проверки

```powershell
Get-ChildItem extension/test-*.cjs | ForEach-Object { node $_.FullName; if ($LASTEXITCODE) { exit $LASTEXITCODE } }
uv run --frozen python -m tools.smoke_audio_page
uv run --frozen --group local python -m tools.smoke_voice_pair
```

Node проверяет PCM, bridge, native framing, отмену старта, изоляцию направлений, очереди, Stop, восстановление после worker restart и HTML escaping. `smoke_audio_page` запускает отдельный headless Chrome с временным профилем, синтетическими RTC-дорожками и IndexedDB. Проверены реальный AudioWorklet, mute, Stop/runtime loss, новая дорожка Meet и сохранность видео. Отчёт: `build/browser-audio-smoke.json`.

Эти проверки не подтверждают настоящий двухсторонний Meet, Chrome tabCapture permission flow или установленный Native Messaging host. Микрофон, камера, профиль пользователя и аудиоустройство в этих инструментах не используются.

`tools.probe_duplex_local` — отдельная проверка с расходом настоящих API: два фиксированных синтетических голоса, временная серверная база, два STT-потока, перевод и локальный Native Messaging синтез. Отчёт без текстов/credentials: `build/duplex-local-probe.json`. Реальный пользовательский баланс не затрагивается. Успех следует определять по `status:ok`, а не по наличию файла; неудачные попытки также сохраняют отчёт. Это тоже не звонок Meet и не проверка качества на слух.
