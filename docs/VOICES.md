# Локальные голоса и подписанный каталог

## Актуально: 0.1.5 / каталог revision4

Доступны пять вариантов: uk-basic (женский Lada, speaker0), uk-male (мужской Mykyta, speaker1 той же закреплённой модели), en-basic (женский LJSpeech), en-male (мужской Joe, CC0-declared, прежний совместимый commit), ru-basic (мужской Denis). Новые мужские варианты прошли реальный синтез: en85548 байт, uk117804 байт. Русский женский вариант не включён, пока нет проверенного совместимого кандидата с подходящими условиями.

Локальный компонент 0.1.1 объявляет remove-voice и удаляет собственный установленный голос только вне звонка с очисткой selection. Сначала деактивируется запись, потом очищается папка; ссылки, reparse и посторонние файлы отклоняются. Сам язык остаётся в общем каталоге. Новые интерфейсные фильтры пола влияют на готовность пары: скрытый выбранный голос другого пола не считается выполненным выбором. Полная инструкция — [LANGUAGES.md](LANGUAGES.md).

Ниже сохранены подробности предыдущих технических этапов.

Реализован технический путь: подписанный каталог → загрузка → размер/SHA-256 → пробный локальный синтез → атомарная активация → выбор голоса → Native Messaging WAV. Проверка на текущем Windows-компьютере не заменяет приёмку в Meet, прослушивание и чистую Windows.

## Доверие и хранение

`catalog/voices.signed.json` содержит Ed25519-подпись над каноническим JSON с отдельным доменом подписи. Публичный ключ и доверенные HTTPS origins закреплены в `local_component/call_translator_local/catalog-trust.json` и включаются в runtime. Расширение не передаёт собственные ключи доверия, пути моделей или произвольные URL. Сервер `/api/voices` также проверяет подпись перед выдачей. `CT_VOICE_CATALOG` может изменить только серверный путь к подписанному манифесту; клиент не выбирает файл сервера.

`tools.build_voice_catalog` создал новый приватный ключ `.tools/voice-catalog-private.key` исключительно для этого проекта. Он не выводится и не включается в Git, runtime или установщик. Не удалять и не заменять его случайно: опубликованный публичный ключ зависит от него. При потере ключа инструмент отказывается незаметно менять доверие. Ключи OAuth и провайдеров в подписи не участвуют.

Проверяются формат/совместимость компонента, ID и версия голоса, обязательные model/config/LICENSE, HTTPS origin, точные размеры и SHA-256. Допускаются только фиксированные имена файлов; архивы или скрипты голосов не исполняются. Revision каталога не может уменьшаться или менять содержимое при том же успешно установленном revision. Конфигурация голоса хранится в подписанном каталоге, а не доверяется редактируемому локальному списку.

Загрузка `.part` переживает прерывание. При HTTP 206 проверяется Content-Range; при ответе 200 на Range загрузка начинается заново. Размер ограничен подписанным значением. Полный неверный файл отбрасывается; старый активный голос сохраняется. Новая версия устанавливается в отдельную папку и активируется заменой `active.json` только после проверки файлов и пробного синтеза. При последующих запусках вновь проверяются сохранённый подписанный манифест и хеши файлов. Голос с повреждёнными файлами не считается готовым.

По умолчанию пользовательские файлы лежат в `%LOCALAPPDATA%\CallTranslatorSaaS\voices`. `CT_LOCAL_VOICE_ROOT` — только локальное окружение процесса для разработки; Native Messaging запрос не может задавать этот путь. Проверки агента использовали `build/local-voices`, пользовательский AppData не изменялся. Выбор для incoming/outgoing сохраняется отдельно. Начало звонка проверяет соответствие языков обоим голосам. OS-lock не даёт другому native-процессу установить или переключить голос во время звонка; lease освобождается при end-call, EOF или завершении процесса.

## Технический образец

Каталог revision 3 содержит `uk-basic` (speaker 0, upstream CC0) и `en-basic` (LJSpeech high, upstream Public Domain). Оба имеют статус `technical_preview`. Исходные MODEL_CARD сохраняются как LICENSE.txt, upstream commit, размеры и SHA-256 закреплены. Это декларации upstream, а не завершённая проверка прав или готовности коммерческого релиза. Добавлен ru-basic (denis medium, декларация CC0 в MODEL_CARD, technical_preview). Проверены WAV 108076 байт и подготовка ru → uk с синтезом обоих направлений; прогрев 38,238 с. Прослушивание и Meet не проверены.

Begin-call проверяет оба выбранных языка и выполняет пробный синтез обоих голосов до ответа call-ready. Холодная загрузка на текущем компьютере заняла около 101 секунды; короткий последующий синтез — около 1,1 секунды для uk и 4,8 секунды для en. Это единичный технический замер, не гарантия задержки. Расширение ожидает подготовку до 180 секунд до подключения платного серверного потока; ошибка прогрева освобождает OS-lock и не начинает звонок.

Русский ruslan из legacy не перенесён в каталог: в его MODEL_CARD указана CC-BY-NC-SA-4.0 для датасета. У irina указана неизвестная лицензия; она также не включена. Для русского выбран отдельный denis с декларацией CC0. Наличие en/ru в серверных адаптерах не делает локальную языковую пару готовой.

```powershell
uv sync --frozen --group local
uv run --frozen --group local python -m tools.smoke_voice
```

Команда проверяет каталог, устанавливает новый голос в `build/local-voices`, синтезирует фиксированную техническую фразу и проверяет аудиочанки. Артефакты: `build/local-voice-preview.wav`, `build/local-voice-smoke.json`. Они не включаются в Git. Это не запись разговора и не тест качества на слух.

`tools.probe_audio_pipeline` — отдельная живая проверка с расходом API. Она синтезирует только фиксированную фразу, отправляет её в украинский STT, параллельно отправляет тишину в английское направление и получает перевод через настоящий серверный WebSocket. Используется временная база и внутренние тестовые credentials; в пользовательском приложении тестового входа нет. В отчёте сохраняются только числовые метрики/статусы, без текстов или токенов. Google OAuth, аудиозахват Meet и воспроизведение в звонке эта проверка не подтверждает.

## Зависимости и лицензии

Группа `local` закрепляет piper-tts 1.8.0, num2words 0.5.14 и cryptography 50.0.2; транзитивные версии зафиксированы uv.lock. Движок используется только в техническом адаптере, в обычном UI его имя не показывается. В файлах обязательной атрибуции и лицензий имя сохраняется. Движок распространяется под GPL-3.0-or-later; перед передачей сборки пользователям необходимо сохранить соответствующие лицензии и обеспечить требуемые исходники. Полный установщик пока не собран и не распространялся.

`tools.build_local_dependencies` устанавливает выбранную группу через uv по lock/hashes в новую staging-папку, не копирует существующий venv. Инвентарь исключает только три примерные ONNX-модели runtime и два нормализатора Arabic/Hebrew, потому что эти языки не поддерживаются. Лицензии и остальные данные пакетов сохраняются; произвольные ключи, .env, connection.json и голосовые модели не попадают в runtime.

Первичные источники: [API локального синтеза](https://github.com/OHF-Voice/piper1-gpl/blob/main/docs/API_PYTHON.md), [пакет и лицензия](https://pypi.org/project/piper-tts/), [upstream украинский MODEL_CARD](https://huggingface.co/rhasspy/piper-voices/raw/main/uk/uk_UA/ukrainian_tts/medium/MODEL_CARD), [ruslan MODEL_CARD](https://huggingface.co/rhasspy/piper-voices/resolve/main/ru/ru_RU/ruslan/medium/MODEL_CARD).
