# Разработка и локальный запуск

Это новый SaaS в отдельном каталоге. Ни один инструмент не требует чтения персонального проекта, его `.env`, connection.json, моделей или сборок.

## Запуск

```powershell
uv sync --frozen
uv run --frozen python -m server
```

По умолчанию: `http://localhost:5086/`, база `data/accounts.sqlite3`, Google-вход и аудиопоток выключены. Это локальный адрес разработки; свободный серверный порт ещё не проверялся. Сервер использует единственный процесс, OS-lock, SQLite WAL и транзакции. Второй процесс с той же базой отклоняется до восстановления звонков. При старте и завершении освобождаются неиспользованные резервы.

Настройки читаются из проектного `.env` и окружения процесса. Загружается только файл в корне этого репозитория, без поиска в родительских каталогах. Окружение процесса имеет приоритет, в том числе при использовании алиасов. `${...}` в значениях не интерполируются, чтобы не изменять секреты. Сам `.env` не меняется, не копируется и исключён из Git. `.env.example` — отдельный шаблон без значений ключей. Значения секретов не передавать в командной строке, Git, чатах или логах.

| Переменная | Назначение |
| --- | --- |
| `CT_DATABASE` | Новый файл SQLite, по умолчанию `data/accounts.sqlite3` |
| `CT_PUBLIC_URL` | Публичный базовый URL без завершающего `/`, например `https://example.org/call-translator-saas` |
| `CT_HOST`, `CT_PORT` | По умолчанию `127.0.0.1`, `5086` |
| `CT_GOOGLE_CLIENT_ID`, `CT_GOOGLE_CLIENT_SECRET` | Новые Google OAuth credentials этого SaaS |
| `CT_DEEPGRAM_KEY`, `CT_GROQ_KEY` | Новые ключи провайдеров этого SaaS |
| `CT_EXPERIMENTAL_AUDIO` | Только `1` включает экспериментальный `/ws`; нужны оба ключа провайдеров |

Поддерживаются также `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `DEEPGRAM_API_KEY`, `GROQ_API_KEY`. Для одного источника заданное `CT_*` имеет приоритет над алиасом. Полностью пустое значение окружения может намеренно отключить соответствующее значение из файла.

```powershell
uv run --frozen python -m tools.check_config
```

Выводит только наличие настроек и флаги, без ключей, их фрагментов, хешей или длины. Содержимое `.env` не выводить через Get-Content, dotenv list или общую печать настроек.

`uv run --frozen python -m tools.probe_providers` выполняет ограниченную **живую** проверку с расходом API: 1 секунда тишины в каждом из ru/en STT-потоков и перевод одной фиксированной технической фразы en→ru (адаптер допускает до одной повторной попытки ответа). Использует временную базу и не затрагивает реальные аккаунты. В `build/provider-probe.json` сохраняются только статусы и числовые метрики, без аудио, текстов и credentials. Команда не включена в unittest и не запускается при старте сервера. Это проверка доступности, не качества речи/перевода и не окончательная экономика.

Google callback: `<CT_PUBLIC_URL>/auth/google/callback`. Для публичного URL обязателен HTTPS. Серверные cookie: HttpOnly, SameSite=Lax, Secure на HTTPS. Для изменяющих браузерных запросов требуются точный Origin и CSRF-токен. Учётные данные в SQLite хранятся как SHA-256, с TTL и отзывом. Одноразовый код устройства действует 5 минут; credential устройства — 30 дней; браузерная сессия — сутки. State входа связан с отдельной браузерной cookie, действует 10 минут и потребляется однократно; используется PKCE и nonce, подпись Google JWT проверяет PyJWT.

OAuth access logger отключён, чтобы не записывать callback-коды. Перед развёртыванием аналогично настроить reverse proxy: в журнал нельзя включать query string OAuth callback или заголовки авторизации. Лимитер использует socket peer, не доверяет произвольному X-Forwarded-For; за reverse proxy он может быть общим для всех пользователей — перед пилотом настроить доверенный proxy и проверить лимиты.

## Проверки

```powershell
uv run --frozen python -W error::DeprecationWarning -m unittest discover -s tests -v
node extension/test-protocol.cjs
node --check extension/background.js
node --check extension/popup.js
node --check server/static/site.js
uv run --frozen python -m tools.smoke_site
```

Последняя команда использует установленный Chrome, отдельный временный профиль и временную базу. Сохраняет `build/site-preview.png`. Это проверка страницы без настроенного Google-входа, не живого OAuth и не кабинета с настоящим аккаунтом. Сервер и профиль после проверки закрываются.

## Экономика и детектор

`Usage.stt_sent` записывает длительность только после отправки PCM провайдеру, отдельно по направлениям. `Usage.translation` записывает usage каждой успешной HTTP-попытки, включая пустой ответ и повтор. Reasoning-токены — часть completion tokens, повторно не умножаются на цену. Неизвестная стоимость при сетевом/HTTP-сбое не выдумывается; отчёт помечен неполным. Метрики не заменяют сверку с фактическими счетами провайдеров.

`uv run --frozen python -m tools.economics --help` — сценарный калькулятор. Все ставки, длительности, токены, комиссии, бесплатные регистрации и возвраты задаются явно. Это сценарий, не измеренная экономика. Цены не утверждены, продажи выключены. Два STT-потока оплачиваются провайдеру и во время бесплатной клиенту тишины. Адаптер Deepgram использует `mip_opt_out=true`: при расчётах брать соответствующую фактическую ставку с учётом влияния этой настройки на цену.

`uv run --frozen python -m tools.evaluate_vad audio.wav annotations.json` проверяет локальный PCM16 mono WAV, 16kHz. Аннотации: `[[start_ms,end_ms], ...]`. Выдаёт precision/recall с шагом 20 мс. Корпус тихой речи, шума, коротких реплик и смены говорящих ещё не получен и не проверен. Без него точность детектора для биллинга не подтверждена.

История использования пока ограничивается последними 100 звонками; автоматическая очистка через 90 дней ещё не реализована. Публичные условия и политика на сайте — помеченные технические черновики, а не готовые документы для продаж. Каталог голосов и аудиоклиент реализованы экспериментально; их проверка описана в `AUDIO_CLIENT.md` и `VOICES.md`. Кабинет владельца, оплаты и бюджетные ограничения перед пилотом ещё нужны.
