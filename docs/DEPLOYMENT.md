# Изолированное развёртывание VPS

Целевой публичный адрес: `https://ppsbot.pp.ua/call-translator-saas`. Он закреплён в поставке расширения; клиент не вводит сервер и не выдаёт разрешения произвольным доменам. Токены старого локального адреса не используются на VPS. Публичная установка домена в настройках не предусмотрена; смена домена — задача выпуска новой конфигурации.

Фактическое развёртывание выполнено 2026-11-05: service enabled/active, current release 20261105-02, HTTPS/WSS и провайдеры проверены, legacy сохранён. Hestia скрывает Upgrade на родительском уровне, поэтому отдельный SaaS include явно содержит `proxy_pass_header Upgrade`. Действующий include совпадает с checkout, nginx -t пройден. Последний воспроизводимый архив с исправлением — `build/vps-release-05.tar.gz`. Google пока отклоняет callback как redirect_uri_mismatch; требуется настройка Console ниже.

## Перед подключением

Нужен явно указанный владельцем SSH-профиль либо хост/пользователь и путь к ключу. Приватный ключ не переносится на VPS и не публикуется в проекте. Подключение проверяет существующий доверенный host key; неизвестный или изменённый fingerprint не принимается автоматически. Извлечение данных доступа из исторического session-log было отклонено автоматической проверкой; этот источник не использовать без явного указания владельца.

В этой сессии пользователь затем явно разрешил прежний ключ/адрес из истории ответом «да»; подключение выполнено именно с этим разрешением. `tools/vps-session.ps1` хранит найденные параметры только в памяти и проверяет сохранённый host key. Точные персональные параметры в документацию не записываются.

До изменений выполнить read-only инвентаризацию: ОС/архитектура/диск, текущие службы, владение портом 5086, наличие `/home/projects/call-translator-saas`, доступный uv и Hestia include hook. Старый `/home/projects/call-translator`, generated-конфиги Hestia и остальные сайты не изменять.

## Содержимое выпуска

`tools.stage_deployment` собирает архив по списку: исходники сервера, статические CSS/JS, pyproject/uv.lock, Python version, проверка публичного каталога/его trust root, deployment templates и проверенный установщик с manifest. `.env`, SSH-ключи, connection.json, локальная база/сессии, голосовые модели и папки разработки туда не входят.

```powershell
uv run --frozen python -m tools.stage_deployment --installer-stage build/installer-stage-02 --output build/vps-release-01.tar.gz
```

Перед распаковкой на сервере сверить SHA-256 архива, проверить имена tar members (без абсолютных путей, `..`, symlink/hardlink), извлечь в новую `/home/projects/call-translator-saas/releases/<release-id>`, затем проверить каждый хеш из release-manifest.json. Не перезаписывать текущий выпуск.

Серверные настройки создаются отдельно в `/etc/call-translator-saas.env` с ограниченными правами. Структура — `deploy/environment.example`, значения новых SaaS credentials не выводить. Локальный `.env` и секреты персонального проекта не копировать. Не включать TTS-группу на VPS: озвучка остаётся на Windows.

## Служба и HTTPS

Используются собственные service user, `call-translator-saas.service`, loopback 5086, SQLite в shared, root-owned releases/current и отдельный Hestia include `nginx.ssl.conf_call-translator-saas`. Готовые templates — в `deploy/`. Их ещё нужно сверить с фактической конфигурацией VPS.

`deploy/install-release.sh` проверяет область путей, существующий custom include hook, принадлежность занятого порта, активные SaaS-звонки и ownership конфигураций. Делает SQLite backup и сохраняет предыдущие собственные конфиги, устанавливает зависимости через отдельный uv, переключает release symlink, проверяет `nginx -t`, запускает только новую службу и проверяет HTTPS SaaS/legacy. При ошибке восстанавливает собственный include/unit/предыдущий выпуск. Generated-конфиги не редактируются. До фактического выполнения этот скрипт не считается проверенным развёртыванием.

Для Google OAuth разрешить точный redirect URI:

`https://ppsbot.pp.ua/call-translator-saas/auth/google/callback`

Это настройка Google Cloud OAuth client, она не меняется клиентским секретом или запуском Python. Не заявлять живой VPS Google-вход до ручного результата.

После развёртывания проверить HTTPS/cookies, страницу кабинета, Google redirect и callback, health/audio=true/sales=false, подпись каталога, WebSocket и выдачу установщика только браузерной сессии. Установщик проверяется по SHA-256 при старте сервера; повреждение не публикуется. Финальный шаг — двухсторонний Meet с новым клиентом. Локальный сервер не является целью пользовательской проверки.
