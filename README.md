# Call Translator SaaS

Отдельный SaaS-проект перевода Google Meet для Windows и Chrome.

Начало работы: прочитать [HANDOFF.md](HANDOFF.md), [IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md) и [AGENTS.md](AGENTS.md).

Сервис развёрнут отдельно на VPS: [кабинет](https://ppsbot.pp.ua/call-translator-saas/account). Проверены HTTPS, WSS, каталог, защита скачивания, Deepgram/Groq с VPS; старый переводчик сохранён. Для Google-входа нужно добавить новый callback в OAuth client: Google пока возвращает redirect_uri_mismatch. Установщик 0.1.1 доступен после входа в кабинет; адрес сервера в расширении не вводится. Озвучка локальная, стенограммы в IndexedDB, сервер учитывает речь, продажи выключены. Полный Meet, чистая Windows и платежи ещё не проверены. Подробности: [состояние](HANDOFF.md), [VPS](docs/DEPLOYMENT.md), [первый звонок](docs/FIRST_CALL.md), [поставка](docs/PACKAGING.md).

Разработка Python — uv. Поставка локального компонента — PyApp + Inno Setup. Один звонок на Google-аккаунт, оплата только времени речи, пять пробных минут после регистрации.

## Локальная разработка

Python 3.11.9 закреплён в `.python-version`, зависимости — в `uv.lock`. Настройки читаются из проектного `.env` и окружения процесса с приоритетом окружения. Секреты в Git не включаются.

```powershell
uv sync --frozen
uv run --frozen python -m server
```

Локальный сайт: `http://localhost:5086/`. Без новых OAuth credentials показывает, что Google-вход не настроен. Публичные тексты условий и политики помечены как технические черновики.

- [Разработка, настройки и тесты](docs/DEVELOPMENT.md)
- [Экспериментальный аудиопротокол](docs/PROTOCOL.md)
- [PyApp и Inno Setup](docs/PACKAGING.md)
- [Голоса и подписи каталога](docs/VOICES.md)

SQLite использует WAL, миграции и транзакции. На аккаунт разрешён один активный звонок, общий предел — пять. 300000 мс начисляются один раз; резерв до 5000 мс возвращается при остановке. Интервалы обоих направлений объединяются без округления. `Accounting.balance()` возвращает доступный баланс без резерва; `/api/account` прибавляет неиспользованный резерв для отображения полного остатка.

Журнал разделяет движение доступного баланса (`trial`, `reserve`, `release`) и расход резерва (`consume`). Суммировать все виды для получения доступного баланса нельзя. Аудио и тексты не сохраняются; в базе остаются интервалы и длительности. Восстановление резервов при старте и завершении сервера подключено; автоматическое расписание backup и очистка истории через 90 дней ещё нужны.

`reference/legacy` — технические образцы с исходной лицензией, не новый дистрибутив. Персональный проект и его сервер не изменялись.
