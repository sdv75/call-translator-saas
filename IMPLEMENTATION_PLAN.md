# Call Translator SaaS — отдельный проект с оплатой речи и расширяемым каталогом голосов

Согласованный план от 2026-11-04. Реализация начата; проверенный прогресс и оставшиеся ограничения отражаются в HANDOFF.md.

## 1. Проект и границы первой версии

Создать SaaS с нуля в отдельном репозитории:

- Локальная папка: `E:\projects\call-translator-saas`.
- Репозиторий: https://github.com/sdv75/call-translator-saas.
- Серверная папка: `/home/projects/call-translator-saas`.
- Название продукта до выбора бренда — **Call Translator**.
- Домен подключить позднее; адреса сайта, API и загрузок задавать конфигурацией.
- Существующий персональный проект и его развёртывание сохранить. Проверенные механизмы захвата, маршрутизации и озвучки использовать как технический образец, перенося необходимые части с тестами и соблюдением лицензий.

Первая версия поддерживает Windows и Chrome, Google Meet, разговоры один на один и группы. В группе расширение использует один человек; остальные говорят на одном общем выбранном языке. Всего два языка.

**Один Google-аккаунт — один активный звонок.** Несколько компьютеров разрешены, одновременный второй запуск отклоняется сервером.

Распознавание и перевод выполняются через сервер, озвучка — локально. Аудиодрайверы не устанавливаются. Пилот распространяется через распакованное расширение; публичная версия — через Chrome Web Store после одобрения и появления первой прибыли.

Первым документом нового репозитория сохранить этот план в `IMPLEMENTATION_PLAN.md`, затем создать собственный `HANDOFF.md` для продолжения разработки.

## 2. Сервер, авторизация и посекундная оплата

Создать новый Python/aiohttp backend. Использовать `uv`, SQLite с WAL, миграциями и резервным копированием. На пилоте один процесс обслуживает независимые асинхронные сеансы.

### Авторизация и сеансы

- Вход только через Google OAuth/OpenID Connect; постоянный идентификатор пользователя — Google `sub`.
- Сайт использует защищённую серверную сессию. Расширение связывается с аккаунтом одноразовым кодом и получает отзываемые учётные данные.
- Ключи Deepgram, Groq и платёжных сервисов хранятся исключительно на сервере.
- Проверка отсутствия активного звонка и создание нового сеанса выполняются атомарно.
- Начальный общий предел — пять одновременных звонков разных аккаунтов; увеличение после нагрузочной проверки.
- Разрывы и аварийные завершения освобождают аккаунт. Второй запуск не прерывает первый.

### Правило оплаты

- **Оплачивается время речи при включённом переводе. Паузы и тишина бесплатны. Кнопки паузы нет.**
- Оплачиваемые интервалы определяются сервером по входящему аудио, а не по сообщениям клиента.
- Детектор речи анализирует оба направления. Пересекающиеся интервалы считаются один раз: одна секунда одновременной речи участников расходует одну секунду баланса.
- Баланс хранится с точностью до миллисекунд, пользователю показываются минуты и секунды. Округление каждого фрагмента вверх до секунды не применяется.
- Загрузка голосов, установка, ожидание ответа модели и воспроизведение уже учтённого перевода отдельно не оплачиваются.
- Во время технического сбоя списание прекращается; разговор останавливается, обычный микрофон восстанавливается. Возобновление — вручную.
- Детектор биллинга не должен вырезать аудио из потока распознавания: бесплатная тишина для клиента сама по себе не означает отсутствие расходов Deepgram.
- Длительные периоды без речи отслеживаются для контроля расходов; после десяти минут без обнаруженной речи сеанс завершается с понятным сообщением.

Бесплатные **300 секунд** начисляются один раз после регистрации, без карты и срока действия. Их можно расходовать частями. Повторный вход и переустановка бонус не восстанавливают.

Начисления, списания, резервирование и возврат неиспользованного резерва выполняются транзакционно. Начальный резерв ограничивается пятью секундами и пополняется по мере расходования.

### Данные и интерфейсы

Добавить API аккаунта, баланса, сеансов, истории, заказов, устройств и каталога голосов. WebSocket-протокол передаёт авторизацию, два аудионаправления, результаты, состояние баланса и причины остановки.

Хранить статистику использования, платежи, операции баланса и расходы провайдеров. Аудио и тексты разговоров в SaaS-базу не сохранять. Стенограммы остаются локальными.

## 3. Экономика, платежи и сайт

### Расчёт до начала продаж

- Измерять длительность отправленного на распознавание аудио отдельно от оплачиваемой клиентом речи.
- Сохранять фактический Groq `usage`, включая повторы и оплачиваемые токены рассуждений.
- Рассчитать сценарии с разным соотношением речи и тишины, бесплатными регистрациями, комиссиями, возвратами и серверными расходами.
- Проверить гипотезу пакетов **100 / 500 / 1500 минут за $9 / $29 / $69** именно для минут речи. Предыдущий расчёт по длительности подключения для этих тарифов неприменим.
- До завершения расчёта цены не считать утверждёнными. На старте — бессрочные пакеты без подписок и передачи баланса.
- Плановый бюджет пилота — до $50 в месяц. Настроить уведомления и ограничение новых бесплатных сеансов и продаж при недостаточном резерве. Учитывать задержку поступления расходов провайдеров.

### Платёжная интеграция

- Первым реализовать Paddle в тестовом режиме.
- До реальных продаж подтвердить подключение физлица из Украины и способ получения выплат, включая имеющийся Payoneer.
- Если подключение не подтверждено, продажи выключены; бесплатный технический пилот продолжает работать.
- Telegram Stars — следующий платёжный этап после проверки возможности получения вознаграждения владельцем.
- Начислять минуты только по проверенному серверному подтверждению. Повторные уведомления не создают повторные начисления.
- Возвраты и компенсации проводить отдельными операциями с журналом действий.

Кабинет пользователя: бесплатный и купленный остаток, активный звонок, история использования, покупки, статусы платежей и устройства.

## 4. PyApp, установка новых языков и голосов

### Сборка и установка

Использовать **PyApp вместо PyInstaller** для запуска локального Python-компонента. Inno Setup остаётся внешним установщиком: он размещает файлы, регистрирует Native Messaging и обеспечивает удаление.

PyApp запускает Python-приложение с подготовкой окружения; это не средство сокрытия исходников. Он поддерживает встраивание Python в исполняемый файл, чтобы не скачивать интерпретатор при запуске. Документация: https://ofek.dev/pyapp/latest/config/distribution/.

- Зафиксировать версии Python, PyApp и зависимостей.
- Включить подготовленный Python runtime и зависимости в поставку: конечный пользователь не устанавливает Python, `uv` или пакеты вручную.
- Первый запуск не должен зависеть от доступности PyPI. Проверить полностью автономную подготовку локального компонента; интернет нужен для аккаунта, перевода и загрузки голосов.
- Устанавливать в пользовательский каталог Windows.
- Пилотный установщик размещает распакованное расширение и объясняет ручную загрузку через `chrome://extensions`.
- Публичный установщик открывает страницу расширения в магазине; подтверждение Chrome выполняет пользователь.
- Обновления компонента проводить вне звонка, с проверкой целостности и откатом. Перед публичным выпуском добавить подпись установщика и исполняемых файлов.

### Как добавляется язык на уже установленном компьютере

1. Владелец публикует проверенный язык и голоса в серверном каталоге.
2. Расширение обновляет каталог при открытии настроек и показывает новые доступные варианты.
3. Пользователь выбирает язык и голос.
4. Локальный компонент скачивает необходимые файлы по HTTPS, проверяет подписанный манифест, совместимость, размер и SHA-256.
5. Файлы устанавливаются в отдельную версионную папку; компонент выполняет пробный синтез и только после успеха активирует голос.
6. Выбор сохраняется. Повторно скачивать расширение и запускать установщик не требуется.

Каталог содержит язык, имя и пол голоса, версию, лицензию, размер, контрольные суммы и минимальную версию локального компонента. Для каждого направления голос выбирается отдельно. Язык с одним доступным голосом остаётся доступным.

Новые модели существующего формата устанавливаются как данные. Если язык требует нового движка или несовместимого формата, сначала предлагается обновление локального компонента. Расширение обновляется только при изменении его интерфейсов или поведения.

Разрешать только доверенные источники каталога; исключить произвольные пути, URL и исполнение скачанных скриптов. Загрузки должны переживать повторный запуск, а незавершённая установка не заменяет работающий голос.

Название движка убрать из обычных сообщений и названий поставки. Лицензии сторонних компонентов и моделей сохраняются.

## 5. Приёмка и развёртывание

### Обязательные проверки

- Тишина не расходует баланс; речь расходует; пересечение направлений не удваивает списание.
- Шум, тихая речь, короткие реплики и переключение говорящих проверены на отдельном наборе аудио.
- Задержки модели и воспроизведение не создают повторную плату.
- Второй звонок одного аккаунта отклоняется без списаний и вмешательства в первый.
- Сбой сети, браузера, провайдера или сервера освобождает сеанс и сохраняет корректный остаток.
- Бесплатные минуты начисляются один раз; поддельные и повторные платежные события не меняют баланс.
- Пользователь не получает чужие данные и не начисляет себе минуты.
- Чистая Windows без Python проходит установку PyApp-компонента и работу расширения.
- Новый голос добавляется без переустановки; повреждённая загрузка и несовместимая модель безопасно отклоняются.
- Живые звонки проверяют оба направления, группу, mute, очереди, собственный перевод, наушники и восстановление микрофона.
- Метрики показывают реальную себестоимость оплачиваемой минуты речи.

### Развёртывание

- Отдельная папка `/home/projects/call-translator-saas`, отдельная служба, пользователь, окружение, база и секреты.
- Выделить свободный localhost-порт после проверки сервера; не занимать порт работающего персонального проекта.
- До покупки домена использовать отдельный HTTPS-маршрут `/call-translator-saas/` на существующем домене.
- Подключать маршрут через отдельный include Hestia; generated-конфиги не редактировать. Перед reload выполнять `nginx -t`.
- При покупке домена обновить адреса, Google OAuth callbacks, разрешённые origins и конфигурацию расширения.
- Предусмотреть резервное копирование, проверку восстановления, метрики, журналы без секретов и откат релиза.

### Порядок реализации

1. Новый репозиторий, документация, структура и воспроизводимое окружение.
2. Проверка PyApp на чистой Windows и измерение экономики оплаты речи.
3. Авторизация, сеансы, баланс, бесплатные минуты и серверный детектор биллинга.
4. Сайт, кабинет и расширение.
5. Каталог, загрузка голосов и установщик.
6. Тестовые платежи, подтверждение выплат и изолированное развёртывание.
7. Закрытый пилот на 10–50 пользователей; продажи после проверки экономики.
8. Исправления, публикация в Chrome Web Store и последующий публичный запуск.

Критерий готовности: **установка → вход → пять бесплатных минут речи → выбор и загрузка нового голоса → покупка → платный разговор → корректные баланс и статистика**, при бесплатных паузах и одном активном звонке на аккаунт.
